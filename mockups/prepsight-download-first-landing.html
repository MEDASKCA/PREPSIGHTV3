The landing page should borrow the rhythm of the app. It can show card shapes, filters, workflow structure and device context without exposing real hospital content or internal screens.

What we should do now

Keep the onboarding you already built. Change the route into it. The landing page should sell the real PrepSight experience and make the app path feel natural.

Lead with the app

The main public page should say download first. That makes sense for a product meant to be used around theatres, wards and departments rather than only from a desktop.

Keep browser as the second route

Some users will still need desktop access. Keep it available, but visually secondary. Existing users can still reach the browser path without friction.

Use real product cues

The public page should feel like PrepSight itself. That means card structure, clean filters, subtle motion and practical language rather than generic marketing blocks.
